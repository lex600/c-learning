# VS Code 使用手册

> 写给零基础的自己。忘了怎么操作就翻这一页。

## 一、先搞清楚：VS Code 和 Dev-C++ 是什么关系

**Dev-C++ 是一个"全家桶"**，把三样东西打包在一起：

| 部件 | 作用 | Dev-C++ | VS Code |
| --- | --- | --- | --- |
| 编辑器 | 打字写代码 | 自带 | VS Code 本体 |
| 编译器 | 把 `.c` 变成 `.exe` | 自带 MinGW 的 gcc | **复用 Dev-C++ 里那个 gcc** |
| 调试器 | 打断点、单步执行 | 自带 gdb | **复用 Dev-C++ 里那个 gdb** |

所以：**两者用的是同一个编译器和同一个调试器。** 编译出来的程序、报的错完全一样。
换 VS Code 只是换了个"外壳"，你的代码一个字都不用改。

严格来说 **VS Code 是编辑器，不是 IDE**——编译器要自己指定。
这一步已经配好了（见 `.vscode/tasks.json`，指向 `D:\app downloads\Dev-Cpp\MinGW64\bin\gcc.exe`）。

## 二、能代替 Dev-C++ 吗

**能，而且推荐。** 取舍如下：

| | Dev-C++ | VS Code |
| --- | --- | --- |
| 写代码体验 | 一般 | 好很多（补全、报错提示、多文件） |
| 编译运行 | F11 | `Ctrl+Shift+B` |
| 调试 | F5，开箱即用 | F5，已配好 |
| Git 版本管理 | 基本没有 | 图形界面，点按钮提交 |
| 还在维护吗 | 原版 2005 年就停止更新 | 微软持续更新 |

结论：**日常待在 VS Code 里，Dev-C++ 留着当备用**，万一 VS Code 出问题还能救急。

## 三、必记快捷键

| 快捷键 | 作用 |
| --- | --- |
| **`Ctrl+Shift+B`** | **编译并运行（最常用，等于 Dev-C++ 的 F11）** |
| **`F5`** | **调试运行** |
| `Ctrl+S` | 保存 |
| `Ctrl+/` | 注释 / 取消注释选中的行 |
| `Ctrl+Shift+G` | 打开源代码管理（提交代码） |
| ``Ctrl+` `` | 打开 / 关闭终端 |
| `Ctrl+P` | 快速打开文件（打几个字母就能跳） |
| `Ctrl+Shift+P` | 命令面板（忘了怎么操作就按它，输关键词搜） |
| `Ctrl+K` `Ctrl+T` | 换配色主题 |
| `Ctrl+Z` | 撤销（可以撤很多步，放心改） |

## 四、每次写代码的完整流程

1. 左侧文件列表里右键 → 新建文件，名字要能看懂，例如 `2026-09-25-函数-统计素数.c`
   ⚠️ **文件名必须以 `.c` 结尾**，否则 VS Code 不知道这是 C 代码
2. 写代码
3. **`Ctrl+Shift+B`** —— 自动编译并运行
   - 编译成功：终端里出现你的程序，需要输入就打字然后回车
   - 编译失败：终端里出现英文报错，**报错里的行号能点**，点了光标会跳过去
4. `Ctrl+Shift+G` → 写一句说明 → `Ctrl+Enter` 提交 → 点「同步更改」推到 GitHub

## 五、调试怎么用（换 VS Code 最大的好处）

调试 = 让程序慢下来，一步一步走，随时看每个变量的值。

1. 在**行号的左边**点一下，出现**红点** = 断点，程序跑到这行会停下来
2. 按 **F5**
3. 会弹出一个黑色控制台窗口（程序真正运行的地方）
4. 程序停在红点那一行，左边出现「变量」面板，能看到所有变量的当前值

调试时顶部会浮出一个小工具条：

| 按钮 | 快捷键 | 作用 |
| --- | --- | --- |
| 继续 | `F5` | 跑到下一个断点 |
| 单步跳过 | `F10` | 执行这一行；遇到函数调用**不进去** |
| 单步调试 | `F11` | 执行这一行；遇到函数调用**进去** |
| 单步跳出 | `Shift+F11` | 从当前函数里跳出来 |
| 停止 | `Shift+F5` | 结束调试 |

**学函数的时候，`F11`（单步进入）是最有用的**：你能亲眼看着程序跳进 `isPrime()` 里面，
看 `n` 是多少、循环走了几圈、在哪一步 `return` 的。这是 `printf` 调试永远做不到的。

## 六、常见问题

**Q：`Ctrl+Shift+B` 没反应？**
A：先确认文件名以 `.c` 结尾；再确认左侧打开的是 `course` 这个文件夹。

**Q：报错是英文，看不懂？**
A：正常，编译器只会说英文。先看**第一行和行号**，后面一大串经常是连锁反应。

**Q：调试时黑窗口里中文乱码？**
A：理论上已经修好了（靠 `.vscode/utf8console.h` 自动把控制台切成 UTF-8）。

**Q：改坏了想回到之前的版本？**
A：这就是 Git 的价值。源代码管理面板里能看到每次改动，右键文件 →「放弃更改」即可还原。

**Q：想换界面语言？**
A：`Ctrl+Shift+P` → 输入 `Configure Display Language` → 选语言 → 重启。

## 七、`.vscode` 文件夹里都是什么

| 文件 | 作用 | 动坏了会怎样 |
| --- | --- | --- |
| `tasks.json` | 定义 `Ctrl+Shift+B` 干什么 | 编译不了 |
| `launch.json` | 定义 `F5` 调试怎么跑 | 调试用不了 |
| `settings.json` | 编译器路径、编码识别、字号 | 头文件会标红报错 |
| `utf8console.h` | 让调试窗口正常显示中文 | 只是中文可能乱码 |

这四个文件都提交到 Git 了，换电脑克隆下来就能直接用，不用重新配。
